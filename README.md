# Slimeworks Level Editor

Отдельный 3D-редактор уровней для **Slimeworks Factory**, написанный на C и raylib. Он создаёт переносимые текстовые файлы `.levl`; игра загружает их сама при старте.

## Запуск

### Windows (VS Code + MinGW)

В проект уже добавлена локальная raylib 6.0 в `../third_party/raylib`. Открой в VS Code папку `Slimeworks-Level-Editor` и нажми `F5`; VS Code сначала выполнит `build.ps1`, затем запустит редактор под `gdb`.

Из PowerShell:

```powershell
.\build.ps1
.\Slimeworks-Level-Editor.exe
```

Для сборки нужен GCC MinGW по пути `C:\ProgramData\mingw64\mingw64\bin\gcc.exe`.

### macOS/Linux

Открой в VS Code именно папку `Slimeworks Level Editor` и нажми `F5`. Конфигурация сначала выполнит `make clean && make`, затем откроет редактор.

Из терминала:

```sh
make
./main
```

## Быстрый старт

1. В новом документе уже есть пол, старт игрока и пример цветного бокса.
2. Добавляй объекты клавишами `A`, `Shift+A`, `P`, `Shift+R` и `K`.
3. Выделяй объект мышью, перемещай стрелками, поднимай и опускай `Q`/`E`.
4. Нажми `Tab` на боксе или Mesh, чтобы перейти в Edit Mode и работать с вершинами, рёбрами и гранями.
5. Нажми `Ctrl+S` — рядом с программой появится `level.levl`.
6. Нажми `F6`. Редактор экспортирует уровень в `../Slimeworks-Factory/levels/factory.levl`.
7. Запусти игру. Если этот файл существует, игра загружает его вместо встроенной тестовой карты.

## Управление

| Действие | Клавиши |
| --- | --- |
| Мышь — схема Blender | MMB — orbit; `Shift` + MMB — pan; `Ctrl` + MMB — плавный dolly; колёсико — zoom |
| Тачпад — macOS и Windows | ПКМ — orbit; `Shift` + ПКМ — pan; `Ctrl` + ПКМ — плавный dolly; scroll — zoom |
| Free mode | `Shift` + `]`; удерживать ПКМ или MMB + `WASD`, `Q`/`E` и мышь; повторить `Shift` + `]` для orbit |
| Ортографический вид — macOS и Windows | `Ctrl+1/2` — front/back, `Ctrl+3/4` — right/left, `Ctrl+5/6` — top/bottom; `Ctrl+7` — top |
| Object/Edit Mode | `Tab` — перейти в Edit Mode или обратно; `Ctrl`/`Cmd` + `Tab` — следующий объект |
| Clipboard | `Ctrl`/`Cmd` + `C` — копировать любой объект; `Ctrl`/`Cmd` + `V` — вставить со смещением |
| Иерархия | Выберите объект → `SET PARENT`, затем выберите любой объект в дереве справа или во viewport; `CLEAR PARENT` снимает связь |
| Выделение объекта | ЛКМ — заменить выделение; `Shift` + ЛКМ — добавить или убрать объект из выделения |
| Создать бокс / mesh / площадку / склон / маркер | `A` / `Shift+A` / `P` / `Shift+R` / `K` |
| Edit Mode: вершина / ребро / грань | `1` / `2` / `3` |
| Edit Mode: выбор | ЛКМ — один элемент; `Shift` + ЛКМ — добавить или убрать элемент из выбора; `Shift` + ПКМ — pan камеры |
| Edit Mode: операции | стрелки и `Q`/`E` — move; `[`/`]` — scale; `,`/`.` — rotate Y; `C` — цвет выбранных граней; `+` — subdivide выбранных граней; `SNAP ALL` — snap всех вершин к мировому grid |
| Edit Mode: весь выбор / снять выбор | `A` / `Alt+A` |
| Импорт модели | `I`, вставить путь, `Enter` |
| Движение | стрелки; `Q` вверх, `E` вниз; `Shift` — крупный шаг |
| Размер | `[` и `]` |
| Поворот бокса или модели | `,` и `.` |
| Gizmo | `G` движение, `R` вращение, `S` масштаб; ЛКМ перетаскивает цветную ось или кольцо |
| Apply Scale | `Ctrl`/`Cmd` + `A` для выбранной статической модели |
| Grid / snap | `Shift` + `S` включить/выключить snap; `Shift` + `,` / `.` изменить шаг сетки |
| Имя / тег | `F2` / `T` |
| Выбранная грань / следующий цвет | `F` / `C` |
| Bevel | `B` увеличить, `N` уменьшить |
| Edge loops у бокса | `+` увеличить, `-` уменьшить |
| Коллизия | `O` |
| Показать AABB коллайдеры | `H` |
| Удалить | `Delete` |
| Сохранить / загрузить | `Ctrl+S` / `Ctrl+O` |
| Экспорт в игру | `F6` |
| Новый стартовый уровень | `F1` |
| Разрешение окна | `F10` — выйти в окно и выбрать 1280×720 / 1600×900 / 1920×1080 / 2560×1440 |
| Полный экран / окно | `F11` |
| Slime Spawn Volume | `V` создать; `[`/`]` размер; `PageUp`/`PageDown` тип; `+`/`-` количество |

Редактор запускается в полноэкранном режиме с разрешением текущего монитора. В оконном режиме окно можно свободно изменять мышью; интерфейс и viewport подстраиваются под новый размер. Частота обновления автоматически берётся у текущего монитора.

## Slime Spawn Volume

`SLIME VOL` — невидимая в игре зона, внутри которой при загрузке уровня случайно появляются залежи заданного типа. Объём можно создавать кнопкой слева или `V`, затем настроить размер, количество и тип в Inspector.

Базовые типы: **Mossdrop**, **Honeykin**, **Azure Puff**, **Emberbud**. Премиальные типы (появляются после открытия второй зоны): **Acidflare**, **Prismcore**, **Aurora Bloom**, **Crownslime**.

## Что умеет редактор

- Боксы с отдельным цветом верхней, нижней, передней, задней, правой и левой стороны.
- Лёгкий **Edit Mode** для Mesh: реальные вершины, уникальные рёбра и quad-грани. Бокс при первом `Tab` конвертируется в Mesh с сохранением цветов сторон и коллизии; после этого вершины, рёбра и грани можно выделять по отдельности или через `Shift+ЛКМ` и трансформировать. Эта геометрия сохраняется в `.levl` и загружается игрой.
- Иерархия объектов: любой объект может быть родителем для любого другого объекта, кроме самого себя и своих потомков. Дерево объектов находится в правой панели Inspector; перемещение, вращение и масштабирование родительской цепочки управляет дочерней геометрией. При `F6` иерархия запекается в мировые трансформации экспортируемого уровня.
- Рабочий bevel и регулируемые edge loops: боковая геометрия разбивается на реальные сегменты при отрисовке и сохраняется в `.levl`.
- Навигация повторяет знакомую схему Blender для мыши; на тачпаде MMB заменяется на ПКМ без дополнительных `Option`/`Alt`-комбинаций. Есть свободный режим, ортографические front/back, right/left и top/bottom-виды, трансформационный gizmo и сетка с шагом `0.125–4` единицы.
- Вместо конечной `DrawGrid` используется прозрачная процедурная сетка: в перспективе она лежит на земле и следует за рабочей областью, а в ортографическом виде разворачивается к камере. Поверни камеру — редактор автоматически вернётся в перспективу и к наземной сетке.
- Площадки и проходимые склоны — они сразу становятся поверхностью для контроллера игрока.
- Теги для любого объекта: например `factory`, `ore_spawn`, `npc_spawn`, `quest_terminal`.
- Невидимые маркеры. В игре они не рисуются, но доступны по имени или тегу. Тег `player_spawn` задаёт точку появления игрока.
- Импорт `OBJ`, `GLB`, `GLTF`, `IQM`, `VOX`; файл копируется в `assets/`, а игра использует полигоны загруженной модели для коллизии.
- `Ctrl`/`Cmd` + `A` запекает scale статичной импортированной модели в новый OBJ и сохраняет её UV и albedo-текстуры. В `.levl` после этого остаётся scale `1,1,1`, поэтому экспорт в игру не использует растягивающий transform.
- Импорт `FBX` через конвертацию в `GLB`. raylib не читает FBX напрямую, поэтому это стабильнее, чем тащить FBX-рантайм в игру. Один раз установи Assimp:

```sh
brew install assimp
```

После этого `I` + путь к `.fbx` автоматически конвертирует его в `assets/<имя>.glb`.

## Теги в коде игры

Парсер добавил удобные запросы в `src/world/level.h`:

```c
Vector3 oreSpawns[16];
int count = LevelFindMarkersWithTag(&game->level, "ore_spawn", oreSpawns, 16);

const LevelModel *terminal = LevelFindModel(&game->level, "quest_terminal");
```

Так точки спавна и импортированные props не привязаны к координатам, захардкоженным в игровом коде.

Полная спецификация файла: [LEVEL_FORMAT.md](LEVEL_FORMAT.md).
